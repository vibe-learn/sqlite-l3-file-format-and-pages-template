        # sqlite — Формат файла и страницы

        Homework-шаблон для урока **l3_file_format_and_pages** (Формат файла и страницы) на платформе Vibe Learn.

        ## Что делать

        На stdlib `sqlite3` (+ чтение файла напрямую) реализуй мини-инспектор формата. Функции:
read_header(path) → словарь {magic, page_size, page_count, freelist_count}, распарсенный из
первых 100 байт файла (магия в [0:16], page_size big-endian в [16:18], page_count в [28:32],
freelist count в [36:40]); is_sqlite(path) → проверяет магическую строку; bloat_ratio(conn) →
оценка фрагментации через PRAGMA freelist_count и page_count; demo_vacuum(conn) → измеряет
размер файла до/после VACUUM. Тесты: создают базу на диске, наполняют, удаляют часть строк,
проверяют, что freelist_count вырос, а после VACUUM файл уменьшился; проверяют корректность
парсинга header (magic == b'SQLite format 3\\x00', page_size — степень двойки).

## Контекст (из transfer-задачи урока)

Ты ведёшь приложение, которое логирует события в таблицу events(id INTEGER PRIMARY KEY,
ts INTEGER, level TEXT, payload TEXT). В payload иногда падают огромные JSON-дампы (по
нескольку сотен КБ). Раз в сутки старые события чистятся большим DELETE. Жалобы:
(1) файл базы за месяц раздулся до 8 ГБ и НЕ уменьшается после ночной чистки;
(2) даже лёгкий запрос `SELECT id, ts, level FROM events WHERE level='ERROR'` стал заметно
    медленнее, чем раньше.

**Вопрос:** объясни на уровне страниц:
(a) почему файл не уменьшается после DELETE и как корректно вернуть место (и какой ценой);
(b) при чём тут overflow-страницы и почему «лёгкий» SELECT без payload всё равно тормозит;
(c) что бы ты изменил в СХЕМЕ, чтобы жирный payload не отравлял горячие запросы;
(d) честно: даёт ли VACUUM «бесплатно» решить всё, или у него есть цена/ограничения
    (блокировка, временное удвоение места на диске)?

## Recap из урока

- Файл SQLite — это **последовательность страниц** фиксированного размера (степень двойки 512–65536, по умолч. 4096); страница — единица I/O. `PRAGMA page_size`.
- Первые **100 байт — header**, начинающийся магической строкой `SQLite format 3\0`. Формат публично документирован → пригоден как архивный.
- Каждая **таблица и индекс — отдельное B-дерево страниц**: table b-tree с ключом rowid (64-бит), index b-tree с ключом-колонками. Корни — в `sqlite_schema`.
- Большие значения уезжают в **overflow-страницы** (связанный список); удалённые/освобождённые — в **freelist** и переиспользуются (файл сам не уменьшается).
- `VACUUM` пересобирает файл компактно (выкидывает freelist, дефрагментирует), но берёт блокировку и требует ~2× места временно. `PRAGMA cache_size` — размер page cache.

        ## Как работать

        1. Платформа Vibe Learn создаёт копию этого репо в твоём GitHub-аккаунте по клику «Начать домашку» на странице урока (через GitHub `/generate`, codecrafters-pattern).

        ## Локальное окружение

        - Python 3.12+
        - SQLite встроена — **никакого сервера и docker-compose**. БД это один файл (`DATABASE_PATH`) или `:memory:` в тестах. Модуль `sqlite3` входит в stdlib, ставить драйвер не нужно — единственная зависимость это `pytest`.

        ## Запуск

        ```bash
        # Установить зависимости (только pytest)
        pip install -r requirements.txt

        # Прогнать тесты (бегут на :memory:-базе, ничего поднимать не нужно)
        pytest

        # Запустить main (печатает marker; замени stub на реализацию)
        python main.py

        # На файловой БД (нужно для backup/vacuum-уроков):
        DATABASE_PATH=./app.db python main.py
        ```
